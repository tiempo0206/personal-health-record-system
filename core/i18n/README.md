# core/i18n/ —— 国际化（中英双语）

## 这个文件夹实现了什么

让用户**在中英两种语言之间切换界面**。它不是某个业务模块，而是核心层的一个能力，
服务于全部 9 个业务模块。

```
core/i18n/
├── README.md              本文件
├── i18n.js                国际化引擎：语言探测、切换、取词、字典拦截、覆盖率统计
├── en-US.js               公共词条：字典层 / 外壳 / 通用 UI / 徽章 / 相对时间
├── en-US.core.js          核心字典与通用组件
├── en-US.auth.js ~ en-US.ux.js   按模块分片的英文词条（清单见文末）
```

> 中文**没有单独的词条文件** —— 中文是源码里的原文，也就是"兜底语言"。
> 详见下面的「兜底式设计」。

---

## 核心设计：`t(key, 中文兜底)`

本项目的中文文案是**内联在代码里**的：96 个 JS 文件、约 9000 行含中文。
一次性全部抽成词条表风险极高（任何一处抽错都会让界面开天窗）。

因此采用**兜底式**设计：

```js
PHR.i18n.t('nav.records', '健康档案')
//             ↑ 词条键      ↑ 中文兜底（源码原文，原样保留）
```

| 情况 | 结果 |
| --- | --- |
| 英文词条存在 | 显示英文 |
| 英文词条缺失 | **自动显示中文兜底**，不会出现空白或 `[missing]` |
| 键名拼错 | 同上，退化为中文 —— 失败是安全的 |

这带来两个好处：

1. **可以逐步翻译**。任何时候往 `en-US.js` 加一条词条，界面上就多一处英文；
   没加的地方照常显示中文，系统始终可用、不会坏。
2. **改动面极小**。调用点只是把 `'健康档案'` 换成 `t('nav.records', '健康档案')`，
   中文行为完全不变，回归风险接近零。

## 杠杆最大的一层：字典

`core/dict.js` 的 `nameOf()` 是全站字典取名的**唯一入口** ——
列表、图表、徽章、筛选器、表单下拉都经过它。因此只要在它内部查一次词条，
**13 张字典表会同时变成英文**。

```
core/dict.js        D.nameOf(list, key)  ← 唯一入口，在这里查词条
       ↑
   list.__i18n = 'gender' | 'severity' | 'diseaseCategory' | …
       ↑
core/i18n/en-US.js  'dict.gender.male' : 'Male'
```

记录类型与体征指标走的是**属性访问器**（`D.recordType(k).name` 这类直接属性访问
全站有几十处，改用 getter 即可全部随语言切换，无需改动调用点）。

**这一层覆盖了全站绝大部分"看起来是数据"的英文**：记录类型名、疾病分类、
科室、医院、用药频次、过敏原类型、授权范围名、审计动作名、16 项体征指标名……

## 语言的决定顺序

`PHR.i18n.detect()` 在 `core/boot.js` 启动时调用一次，顺序为：

```
① URL 上的 ?lang=xx        ← index_enUS.html 用这个，强制英文
② 用户上次在界面里的选择     ← 持久化在偏好设置里
③ 默认 zh-CN
```

**① 与 ② 的区别很重要**：

| | 生效范围 | 是否写回偏好 |
| --- | --- | --- |
| `?lang=en-US` | 仅本次会话 | ❌ 不写回 |
| 界面上切换语言 | 一直有效 | ✅ 写回 |

所以：

- 双击 **`启动网站_enUS.bat`** → 永远是英文，不管上次选了什么；
- 双击 **`启动网站.bat`**（= `index.html`）→ 默认中文，尊重你上次在界面里的选择；
- 在界面里点 🌐 切换 → 记住这个选择。

> ⚠️ **③ 为什么不是浏览器语言**：`navigator.language` 跟随的是操作系统的
> **显示语言**，不是区域。在"显示语言 English + 区域中国"的机器上（公司统一
> 镜像里很常见）它返回 en-US，于是默认入口打开就是英文，和英文入口毫无区别。
> 本项目是中文演示系统，默认入口就应当是中文 —— 要英文请走 `index_enUS.html`。
> 这条回退已于 2026-09-15 移除。

## 怎么用

### 用户

- 顶栏的 **🌐** 图标 → 选择语言
- 「偏好与安全」页面也会同步这个设置

### 开发者：新增一处翻译

1. 在视图里把中文换成 `PHR.i18n.t('键名', '中文原文')`
2. 在 `core/i18n/en-US.js` 加一行 `'键名': 'English'`
3. 完成 —— 不需要改任何其它文件

**词条命名约定**：

| 前缀 | 用途 | 例 |
| --- | --- | --- |
| `dict.<字典组>.<key>` | 字典层 | `dict.severity.moderate` |
| `view.<视图名>.title` | 页面标题 | `view.records.title` |
| `nav.<名称>` | 导航 | `nav.settings` |
| `ui.<名称>` | 通用组件 | `ui.cancel` |
| `<模块>.<名称>` | 模块内文案 | `assessment.take.submit` |

### 开发者：给一个字典表加翻译

在 `core/dict.js` 里给数组打组名标记（已有 16 张表打过）：

```js
D.tagDict(D.gender, 'gender');
```

然后在 `en-US.js` 里加 `'dict.gender.male': 'Male'` 即可。

## 覆盖率：已实测 100%

`PHR.i18n.coverage()` 会统计字典层的翻译进度，语言选择对话框里**直接显示这个数字**。

这是刻意的：英文模式下未翻译的内容会显示中文原文，与其让用户困惑
"为什么一半中文一半英文"，不如把进度说清楚，并告诉他
「界面上看到哪句还是中文，在 `core/i18n/en-US.js` 加一条即可」。

   疾病分类、科室、医院、体征指标、授权范围、审计动作、严重程度、性别血型…）、

   含健康洞察的六类告警与 9 个风险维度、账号安全、工作台、
   患者社群、**使用帮助 28 篇正文**、**演示数据（含社群散文）**、**心理测评全模块**，
   以及新增的报告导入、搜索匹配原因、健康洞察数据来源说明。

2. **医疗术语的翻译口径**已在 `en-US.js` 文件头写明：采用国际通行英文医学表达
   （Hypertension 而非 High blood pressure），量表名保留原始缩写（PHQ-9 / GAD-7），
   分级用描述性词汇避免暗示诊断。

3. **量表题目已有英文界面词条，但真实医疗/研究场景要换成授权且验证过的正式量表译本**。
   本项目的英文题目只服务演示界面一致性，不应作为临床诊断依据。

4. **日期格式未本地化**。`PHR.util.fmtDate` 固定输出 `YYYY-MM-DD`，
   中英通用，未按 locale 调整。

5. **`?lang=` 不写回偏好**是刻意的（见上文），如果你希望英文启动器也改变默认语言，
   把 `i18n.js` 的 `detect()` 里 `forced` 分支的 `persist` 打开即可。

## 踩过的三个坑（写新代码时注意）

1. **加载期取词会永久冻结成中文。** `i18n.detect()` 在 `core/boot.js` 里跑，而它最后加载。
   任何在模块加载阶段求值的 `PHR.t()` 都会拿到默认的 zh-CN 并固化。
   → 解决：用 `Object.defineProperty` 取值器；或在渲染/调用时才取词。
   （`?lang=` 已在 `i18n.js` 加载完时先行应用，覆盖启动器场景。）
2. **内部枚举不要翻译。** 趋势方向、风险等级、建议分组等值在多个模块间用 `===` 比较，
   翻译它们会静默破坏逻辑。→ 解决：显示处用 `PHR.t('phrase.' + 值, 值)` 查短语表。
3. **字典要经 `D.nameOf()` 取，不要直接读 `hit.name`。** 后者绕过了国际化拦截
   （`badge.js` 的 severity/actionRisk 就踩过这个坑）。
